# 1. Set up OpsBrain

This guide takes you from an empty server to a running OpsBrain with your first people, agents and keys. Plan on about an hour. Everything runs on hardware you control: the database, the server, the embedding model and the human-readable PARA mirror.

**You need**

- A Linux server or VM you control (4 GB RAM is enough without local embeddings; 8 GB or more with them). A home lab node, a small VPS or a Kubernetes cluster all work.
- Docker with the Compose plugin (or a Kubernetes cluster, see [Kubernetes](#kubernetes)).
- A way to reach the server privately: a VPN (WireGuard, Tailscale), or a reverse proxy or tunnel with TLS. Never publish port 8787 directly.
- A password manager or secret store for the keys you will create.

**What you get**

| Container | What it does |
| --- | --- |
| `db` | Postgres 16 with pgvector. Not published outside the Docker network. |
| `opsbrain` | The MCP server. Applies database migrations on start, then serves `POST /mcp` and `GET /healthz` on port 8787 (bound to localhost). |
| `para-export` | Writes the PARA markdown mirror at 00:00, 06:00, 12:00 and 18:00 (your `TZ`) and once on start. |
| `ollama` (optional) | Local embedding model for semantic search, so record text never leaves your server. |

## Step 1. Get the code

```bash
git clone https://github.com/gen-skeptic/OpsBrain.git opsbrain
```

```bash
cd opsbrain
```

## Step 2. Configure

```bash
cp deploy/.env.example deploy/.env
```

Edit `deploy/.env`. At minimum:

- `POSTGRES_PASSWORD`: a long random value (`openssl rand -base64 32`).
- `OPSBRAIN_PUBLIC_URL`: the address people and agents will use, for example `https://opsbrain.yourdomain.internal`.
- `TZ`: your time zone. The four daily exports run at local time.
- `EMBEDDING_*`: leave the defaults to use local Ollama (Step 3), or set `EMBEDDING_PROVIDER=none` to start with keyword search only. You can add embeddings later and backfill them with `reembed`.

> `EMBEDDING_DIM` is fixed when the database is first created. The default (768) matches `nomic-embed-text`. If you choose another model, set its dimension before the first start.

`deploy/.env` is gitignored. Do not commit it.

## Step 3. Create the mirror folders

The exporter runs as user 1993 inside its container. Create the output folders and give it ownership. Keep the restricted folder private.

```bash
mkdir -p para-output para-restricted && sudo chown 1993:1993 para-output para-restricted && sudo chmod 700 para-restricted
```

To export restricted records (HR, salaries, legal), set `PARA_RESTRICTED_DIR=/data/para-restricted` in `deploy/.env`. Leave it empty to keep restricted records out of every markdown file.

## Step 4. Start

With local embeddings (recommended):

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env --profile local-ai up -d --build
```

Without local embeddings:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build
```

Check that it is healthy:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env ps
```

```bash
curl -s http://127.0.0.1:8787/healthz
```

You should see `{"ok":true}`. The `ollama-pull` container downloads the embedding model once and exits.

For the rest of this guide, this alias saves typing (run it in each new shell):

```bash
alias ob='docker compose -f deploy/docker-compose.yml --env-file deploy/.env exec opsbrain deno task admin'
```

## Step 5. Add the owner

Create yourself as the owner. `--can-approve` gives you the right to approve financial and ethical decisions; only people (never agents) can hold it.

```bash
ob principal add erich --name "Erich Dautel" --kind human --role owner --can-approve --title "Founder"
```

Roles:

| Role | Can do |
| --- | --- |
| `owner` | Everything, including reading restricted records and acting as any agent. |
| `admin` | Same as owner for records; meant for operations staff. |
| `member` | Read company records, create records, change records they own, are assigned, or created. |
| `agent` | Same as member. Used for AI agents. |
| `auditor` | Read company records. Cannot write. |

## Step 6. Load your company structure

A seed file creates areas of responsibility, processes, agents, people and delegations in one idempotent step. Start from [`deploy/seed.example.json`](../../deploy/seed.example.json), or use the one generated by the experts repo (`opsbrain/seed.json`), which defines all 48 Dautel agents, the 45 work processes and their areas.

Copy the file into the container and load it:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env cp ./seed.json opsbrain:/tmp/seed.json
```

```bash
ob seed /tmp/seed.json
```

Seeding is safe to repeat. Re-run it after you add agents so `"all-agents"` delegations include the new ones.

You can also add things one at a time:

```bash
ob area add finance --name "Finance and administration" --owner erich --order 10
```

```bash
ob project add ACME-01 --name "Acme customer portal" --kind client_engagement --client "Acme" --area service-delivery --owner erich
```

## Step 7. Issue keys

Every person, agent runtime and service gets its own key. Keys are shown once and stored only as a SHA-256 hash.

```bash
ob key issue erich --label "laptop claude code"
```

Store the printed `obk_...` value in your password manager or secret store.

**One key per agent, or one key for many agents?** Both work:

- **Separate keys** (one per agent) are best when agents run independently, for example in OpenClaw or Hermes on different hosts.
- **A delegated session key** is best when one AI session plays many roles, for example the experts repo in Claude Code. Create a service principal, delegate it to the agents, and give that session the key. Each call names the agent with `acting_as`, and OpsBrain records both the agent and the key that was used.

```bash
ob principal add erich-claude-code --name "Erich's Claude Code" --kind service --role agent --responsible erich
```

```bash
ob delegate erich-claude-code --all-agents
```

```bash
ob key issue erich-claude-code --label "experts repo" --expires-days 180
```

Rotate and revoke:

```bash
ob key list erich-claude-code
```

```bash
ob key revoke <first-8-or-more-characters-of-the-hash>
```

Disable someone who leaves (their records and history stay):

```bash
ob principal disable sam
```

## Step 8. Publish it privately

Put OpsBrain behind TLS on an address your team can reach. Pick one:

- **VPN only** (most private): Tailscale or WireGuard, with a reverse proxy (Caddy, Traefik, nginx) on the VPN address. Works for Claude Code, Codex, OpenClaw and Hermes running on machines on the VPN.
- **Tunnel** (needed for Claude Desktop and claude.ai custom connectors, which connect from Anthropic's cloud): a Cloudflare Tunnel or similar to `http://127.0.0.1:8787`, with HTTPS. Keys still protect every request. Consider an access policy that allows only `/mcp` and `/healthz`.

Set `OPSBRAIN_PUBLIC_URL` to the final address and restart:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

## Step 9. Connect your AI clients

See [Connect clients](02-connect-clients.md). Then ask your client: "Call whoami on OpsBrain." It should answer with your handle and role.

## Step 10. Back up

OpsBrain is the company's system of record. Back it up before you rely on it.

Nightly logical backup (keep copies on storage you control, encrypted):

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env exec -T db pg_dump -U opsbrain -Fc opsbrain > "opsbrain-$(date +%F).dump"
```

Restore into an empty database:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env exec -T db pg_restore -U opsbrain -d opsbrain --clean --if-exists < opsbrain-YYYY-MM-DD.dump
```

The PARA mirror is a readable copy, not a backup: it leaves out history beyond the last 15 events, embeddings and keys.

Test a restore at least once a quarter.

## Kubernetes

`deploy/k8s/` has a Kustomize base: the server Deployment (with a migration init container), a ClusterIP Service, the PARA CronJob (`0 0,6,12,18 * * *` with `timeZone`), a PVC for the mirror, a ConfigMap, an example Secret and an optional CloudNativePG cluster with pgvector.

1. Install the database. With the CloudNativePG operator, apply `deploy/k8s/postgres-cnpg.yaml` and use the generated `opsbrain-db-app` secret's `uri` as `DATABASE_URL`. With any other Postgres, run `CREATE EXTENSION vector; CREATE EXTENSION pgcrypto;` as a superuser first.
2. Build the image from `deploy/Dockerfile` and push it to your private registry; set it in `deploy/k8s/kustomization.yaml`.
3. Create `opsbrain-secrets` from `deploy/k8s/secret.example.yaml` (encrypt it with SOPS or use your secret manager).
4. Edit `deploy/k8s/configmap.yaml` (public URL, embedding endpoint, time zone).
5. Apply:

```bash
kubectl apply -k deploy/k8s
```

Run admin commands in a server pod:

```bash
kubectl -n opsbrain exec deploy/opsbrain -- deno task admin principal list
```

The mirror lands on the `opsbrain-para` volume. To read it, either enable `PARA_GIT_COMMIT` and push to a private git server, or mount the volume read-only into a file server you already use.

## Run without Docker

You need Deno 2.5 or later and a Postgres 16 with pgvector.

```bash
export DATABASE_URL=postgres://opsbrain:...@localhost:5432/opsbrain
```

```bash
deno task start
```

```bash
deno task para:schedule
```

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `Unauthorized: missing, invalid, revoked or expired OpsBrain key` | Check the header name (`x-opsbrain-key` or `Authorization: Bearer`), that the key is active (`ob key list <handle>`), and that the principal is enabled. |
| `thoughts.embedding has N dimensions but EMBEDDING_DIM is M` | The database was created with another dimension. Use a model with that dimension, or start a new database. |
| Records say "saved without an embedding" | The embedding service was unreachable. Records are saved and keyword search works. Fix the service, then run `ob reembed`. |
| `permission denied` from the exporter | The mirror folders are not owned by user 1993 (Step 3). |
| `<handle> is not allowed to act as <agent>` | Delegate the key's principal to that agent (`ob delegate <handle> <agent>`), or use the agent's own key. |
| `Approvals must come from a person with approval rights ...` | Approvals need a human with `--can-approve`, using their own key without `acting_as`. |
